## 0. 总体结论

**当前版本不是一个可玩的第一章，而是一个"UI 壳 + 一块被 UI 盖住的黑色画布"。**

| 维度 | 结论 |
|---|---|
| 画面 | 点击 Start 后 3D 视口**纯黑**（场景里没有任何灯光）；加灯后也只是一片绿色平面 + 一个圆锥形"爱丽丝" |
| 流程 | 真实输入下，**只有一条**状态跳转（S2→S3）能发生；S0→S1、S1→S2、S3→S4…→END 全部只能靠测试后门 `window.__game.goto()` 瞬移 |
| 角色 | 爱丽丝 = 圆锥 + 2 个球 + 1 片平面，无脸/手/腿/发型/蝴蝶结；远低于"《小王子》那种一眼可识别、特征鲜明"的角色设计水准 |
| 剧情 | 54 条 Carroll 台词**一条都不会在游戏里出现**（无人触发 `dialogueTrigger`）；过场只置 flag、等 1.2 秒 |
| 测试 | `lint` 是 `echo`；`test` 带 `|| echo` 兜底；单元测试自己断言自己；E2E "通关"是 `setFlag` 后再断言 flag；7 张"E2E 截图"字节完全相同（全是标题页） |
| 构建 | `typecheck` / `build` 通过；单元测试 18/18 通过（但见上，测试本身不可信） |

## A. 美术 / 角色 / 场景（**用户点名，最高优先级**）

### A-01 [P0] 爱丽丝建模：只是"三角形"，必须做到《小王子》级别的细节与辨识度

**现状（证据：`E05`；`src/game/entities/AliceEntity.ts:13-40`）**
- 游戏里实际显示的爱丽丝由 Three.js 基础几何体拼成，共 4 个网格：
  1. 圆台（`CylinderGeometry(0.15, 0.25, 0.6)`）当身体——从正面看就是一个三角形；
  2. 球当头；3. 略大的球当"头发"；4. 一片单面 `PlaneGeometry` 当围裙（从背面看消失）。
- **没有**：脸（眼睛/眉毛/鼻子/脸颊/嘴）、脖子、手臂、手、腿、长袜、玛丽珍鞋、卷发、蓝丝带蝴蝶结、泡泡袖、彼得潘领、围裙肩带荷叶边、口袋、背后的蝴蝶结腰带。
- 裙子颜色是蓝绿 `#4A7C59`，规范是小麦黄 `#E9C46A`（`CLAUDE.md` §3）。
- 总高约 1.1 m（头顶球心 0.97 m + 半径 0.13 m），不是 1.20 m；Alice 移动时朝向角算出来了但**从未应用到网格**（`CharacterController.ts:92` 写入 `rotation.y`，`AliceEntity` 不读取），所以她永远面朝一个方向"滑行"。
- 另有一份 `public/assets/models/chr_alice.glb`（3.5 KB / 58 顶点）：1 个圆柱 + 1 个盒子围裙，**连头都没有**，无骨架、无动画（`animations: 0`），且游戏代码**根本不加载它**。它由 `tools/generate-procedural-assets.mjs:329-341` 用基础体生成，不是 Blender 建模。

**目标（验收标准，见任务书 WP-2 的完整清单）**
爱丽丝必须是一个有设计感、剪影一眼可认的主角，类比《小王子》——标志性特征极其鲜明：在游戏默认镜头距离（3.2 m、1280×720）下，仅看**纯黑剪影**也能认出"大块波浪长发 + 头顶蝴蝶结 + 泡泡袖 + 外扩的及膝裙 + 背后大蝴蝶结腰带"。
- 比例：头身比 **1:4.5**（头高约 0.27 m）；手、脚略夸张以便第三人称读得清
- 头发：浅金色 `#E6C98F` 波浪长发，披到中背，用雕塑成束的发块（不是球，也不是面片发卡），头顶**藏青 `#2E3F6E`** 丝带 + 扁平蝴蝶结
- 脸：大而有神的深榛色眼睛（带高光）、眉毛、小圆鼻、红扑扑的脸颊、嘴；至少 4 个表情形态键（平静 / 惊讶 / 哭泣 / 微笑）
- 服装：小麦黄及膝连衣裙 `#E9C46A`、短泡泡袖、古董白圆领；**白色亚麻围裙 `#F7F3EA`**（荷叶边肩带、两个前口袋、背后蝴蝶结腰带）；及膝罗纹白袜；黑色单带玛丽珍鞋 + 小铜扣
- 禁止：浅蓝裙 + 黑发带的组合（`CLAUDE.md` §3 "No-Disney"）；也不得照搬《小王子》或任何影视改编的造型——《小王子》只是**细节与辨识度的参照物**，造型必须遵循 Tenniel 1865 插画与本项目配色
- 技术：多边形预算 LOD0 约 1 万–1.8 万三角面；带人形骨架 + 头发/裙摆/腰带次级骨骼；挂点 `SOCKET_HandR` / `SOCKET_HandL`；手绘风格贴图（≤2048）；封闭网格 + 平滑法线，兼容反向外壳描边
- 动画片段（名称必须与过场 JSON 一致）：`Alice_Idle` `Alice_Walk` `Alice_Run` `Alice_TryDoor` `Alice_CrawlIn` `Alice_Land` `Alice_CurtseyAir` `Alice_KneelPeek_In/Out` `Alice_Drink` `Alice_ShrinkReact` `Alice_Slip` `Alice_SitCry` `Alice_Eat` `Alice_LookDown`

> 制作建议：本机已有 Blender 5.2（`/mnt/d/blender.exe`）和 Blender MCP（`127.0.0.1:9876`，见 `.agents/teamwork/ORIGINAL_REQUEST.md`），应在 Blender 里真正建模/绑定/做动画，而不是再用 Node 脚本拼基础体。

## B. 玩法 / 流程

### B-01 [P0] 点击 "Start Journey" 之后状态仍是 `S0_TITLE`
- `UIManager.ts:230-234` 只隐藏标题页并发 `startJourney`；全仓库唯一的监听者是 `AudioManager` 的音频解锁（`AudioManager.ts:85`）。**没人把状态推到 `S1_BANK`**（运行验证：点击后 `getState().state === 'S0_TITLE'`）。
- 同时 `btn-continue-journey` 永远 `hidden`，没有任何检测存档的逻辑（运行验证）。

### B-02 [P0] 状态链断裂：整个源码里只有 1 处 `stateMachine.goto()`
- `GameManager.ts:106`（S2→S3）。S1→S2、S3→S4、S4→S5、S5→S6、S6→S7、S7→END **没有任何真实触发**；只有 `testHarness.ts` 能瞬移。
- 运行验证：S1 下连按 E、再空等 46 秒，状态仍为 `S1_BANK`（规范：摘第 2 朵雏菊或 45 秒触发 C1 并进入 S2）；S2 按 E 后进入 `S3_FALL`，再等 20 秒仍停在 `S3_FALL`（规范：t=88s 自动着陆 → S4）。

### B-03 [P0] 交互系统是桩：没有距离判定、没有射线、没有提示
- `GameManager.handleInteraction()`（`:97-111`）：S1 下**任意位置**按 E 都会 `addItem('daisy_1')`、把 `daisiesPicked` 直接写成 2、播 C1；再按 E 会重复加入 `daisy_1`（运行验证：3 次 E → 背包 3 个 `daisy_1`，且都显示成钥匙图标 🗝️，见 `E09`）。S2 下任意位置按 E 即跳进兔子洞；S5 下任意位置按 E 即记一次"试门"。
- 完全没接线：姐姐的书、第 1/3 朵雏菊、拿钥匙、窗帘、小门、取瓶子、爬桌腿、开盒子、吃蛋糕、`INT_*` 目标点。
- `showPrompt` / `hidePrompt` 有监听者但**无人发出**，所以不会出现 `[E] Examine` 提示；`PhysicsWorld.addTriggerVolume` 从未传入回调，所有 `TRG_` 永远不会触发（读码）。

### B-04 [P0] 过场系统不执行时间轴
- `CutscenePlayer.playCutscene()`（`:60-80`）读取 JSON 后**不处理 `events`**（camera 11 / dialogue 14 / animation 9 / audio 5 / scale 1 / state 1，共 41 个事件全被忽略），立刻把 `terminalFlags` 和写死的 `switch` 里的 flag 全部置位，然后固定等 **1200 ms**（`:72`）结束。规范是 4.5–10 秒的演出。
- `applyTerminalState` 的硬编码会"白送"结果，例如 C3 直接 `jarStored = true`（玩家没有放罐子）、C4 直接 `doorsTried = 4`、C5 直接 `littleDoorOpened/bottleAppeared = true`。
- INV-06"跳过与观看等价"因此是**同义反复**：播放本身就等于跳过。
- 跳过路径有两套互不相通：`InputManager` 发 `ESC_SKIP`（松开时 ≥ **0.5 s** 即触发，`InputManager.ts:37`，规范是 **1.0 s**），`UIManager` 另发 `skipCutscene`（无人监听）。

### B-05 [P0] 对白 / 字幕 / 好奇笔记 / 结算页 / 卡关提示全部"有 UI、无触发"
- `dialogueTrigger` 有 2 个监听者（UI + 音频），**零个发射者**（运行验证：C1 播放期间字幕框始终隐藏）。`ch1.json` 的 54 条台词在游戏中一条都不会出现。
- `showCuriosityNote`、`chapterComplete` 同样无发射者 → 5 条好奇笔记与"第一章结束"结算页永远不可达（`goto('END')` 后 `ui-chapter-complete` 仍为 `hidden`，运行验证）。
- 缺少"当前目标"HUD（规范 S1 要求出现 *"Follow the White Rabbit"*）。

### B-06 [P0] S3 "90 秒坠落" 玩法完全缺失
无浮动原点、井筒滚动（2.2 m/s）、1.4 m 半径内漂移、橘子酱罐拾取/不可丢弃（INV-07）/放入壁橱、5 个思想气泡（t=10/30/45/58/70s，漏掉 10 秒后重生）、`C` 键空中屈膝礼（输入层发了 `'C'` 事件但没人监听，`curtsey` 永远为 false）、t=75s 薰衣草暮色 + Dinah 幻影、t=88s 黑屏 + "thump! thump!" → C3。

### B-07 [P1] 瓶子 3D 检视（INV-05）是假实现
- `UIManager.openInspector()`（`:444-479`）里"3D 检视"是一个 emoji 🍾；`mousemove` 一动就算"正面已检视"，累计约 19 次鼠标移动（`inspectRotationY += 10` > 180）就算"背面已验证"。
- 真正跟踪旋转角的 `ItemInspector.ts` 没有被 UI 使用——两套互不相连的实现。"Drink" 按钮也不存在于模态框中。

### B-08 [P1] 缩小过程（INV-04）未达标
- `CharacterController.setScale(…, smooth=true)` 从未被调用；平滑分支用的是指数逼近而非规范的"2.5 秒三次 ease-in-out"（`:76`）。
- 缺少望远镜式圆形暗角、脚步 1.6× 变调的实际接线、胶囊体半径 0.18→0.04（现为 0.25→0.08）、速度 1.4→0.5 m/s（现为 2.5→1.0）、相机距离 3.2→0.8（有）与相机 FOV 平滑（有）。

### B-09 [P1] 谜题不变量的落地情况
- INV-01 窗帘锁：`canAccessCurtain()` 逻辑存在，但世界里的窗帘没有任何交互/高亮/射线（A-03、B-03）。
- INV-03 钥匙自动归位：只改了背包数组与 flag，场景里钥匙模型位置不变。
- INV-07 罐子禁丢：`tryDropJar()` 没有输入绑定；无罐子。
- 钥匙试门 ×2 → 窗帘揭示 → 小门 → C5 → 瓶出现的链条在运行时不可达。

### B-10 [P1] 卡关提示（60s/120s）实际不会显示
- `UIManager.startIdleTimer()` 用 `currentGameState`（取值如 `S1_BANK`）去查 `getStuckHint(state, …)`，而 `ch1.json.stuckHints` 的键是 `S1`…`S7`（`i18n.ts:79-87`），**永远查不到**，提示被吞掉（读码；已对照 JSON 键核实）。

### B-11 [P1] 存档
- `StateMachine.setFlag()` 每次都 `saveState()`（`:64-67`），而 `PuzzleManager.update()` **每帧**调用 `setFlag('idleSeconds', …)`（`:17`）→ 每帧一次 `JSON.stringify + localStorage.setItem`（运行验证：无头软渲染 3.6 fps 下 2 秒写入 7 次，真机约 60 次/秒）。规范是"每个场景边界保存一次"。

### B-12 [P2] Esc 暂停菜单不暂停

### C-01 [P1] 角色控制器没有碰撞、没有朝向、速度不符

### C-04 [P1] 物理 / 触发器

- 触发器检测用 `Box3.containsPoint(playerPosition)`（点判定，忽略玩家胶囊），且回调从未注册（B-03）。
