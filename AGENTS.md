# AGENTS.md — read this first (all coding agents: Antigravity, Claude Code, Codex, …)

Project: **Alice: Down the Rabbit-Hole** (Vite + TypeScript + Three.js, Blender/bpy asset pipeline). Rules of the house: `CLAUDE.md`.

## The hard stop rule (do not negotiate it)

> **Do not stop, hand over, or say "done" until `npm run gate` exits with code `0` and `docs/devlog/gate/VERDICT.md`
> (written after the last capture, from a side-by-side look at `docs/devlog/gate/board.png`) says `Verdict: PASS`.**

* Exit `1` = checks are failing → keep working. Exit `2` = you only ran `--quick`/`--no-run` → that is not a completion signal.
* Running out of context/time is **not** a reason to stop: write the failing-check list and next steps into
  `docs/review/REMEDIATION_LOG.md`, commit, push, and continue from `npm run gate -- --no-run`.
* The bar is the *Little Prince* (https://littleprince.dev/) level of painted finish and modelling — numbers in
  `docs/art/benchmark/`, thresholds in `docs/review/gate-thresholds.json` (they may only be **raised**).
* Never edit `tools/lib/image-metrics.mjs`, `tools/quality-gate.mjs`, `tools/check-assets.mjs`, the thresholds downwards, or the fixed
  camera views in `tests/e2e/visual_parity.spec.ts` to make a number pass; never add noise/texture stickers to inflate image metrics;
  never skip/weaken tests; never write state or teleport through `window.__game`.

### Repository rules (all agent tools, including Google AI Studio / Antigravity)

* **Never push to `main`.** Work on a topic branch, open a PR, wait for the `CI Pipeline` checks to be green. A merged PR's branch is finished: do not reuse it.
* **npm only.** `package-lock.json` is the single lockfile; do not delete it and do not add `bun.lock`. CI uses `npm ci`.
* Dev server: `npm run dev` (port 3000, also used by Playwright). UI is React 19 (`src/main.tsx`, `src/App.tsx`); the engine stays framework-free.
* One concern per PR. Any visual change needs a fresh `npm run gate` capture and a before/after `docs/devlog/gate/board.png` in the PR description.
* Never add write access to `window.__game` / `window.__lab` (the test harness is read-only), never commit tool scratch folders (`.aistudio/`).
